# Research & Technical Decisions: Core Satellite Tracking & Globe Experience

**Feature**: `001-core-satellite-tracking`  
**Date**: 2026-11-07  
**Status**: Completed

## 1. 3D Globe Rendering Engine

### Decision
Use **Three.js** (via standard WebGL renderer) with procedural wireframe latitude/longitude sphere geometry, custom shaders/line materials, and smooth camera controls.

### Rationale
- The visual design in `design/Default-globe.png` demonstrates a precise, minimalist wireframe Earth: latitude parallels, longitude meridians, subtle atmospheric silhouette, and background celestial star points.
- Three.js provides high-performance GPU-accelerated rendering, handles point particles and line trails effortlessly (consistently maintaining 60 FPS), and gives full programmatic control over camera raycasting (for clicking satellite points directly on the globe), camera targeting/focus transitions, and dynamic orbit path lines.
- Extremely lightweight footprint with zero heavy GIS baggage (Cesium/NASA WorldWind are too heavyweight and enforce Earth textures/styling that conflict with the custom mission-control aesthetic).

### Alternatives Considered
- **CesiumJS**: Full-featured aerospace virtual globe, but extremely heavy (>30MB), brings complex terrain/imagery default engines, and overrides custom minimalist wireframe styling.
- **globe.gl**: High-level wrapper built for textured globes with blue atmospheric glow shaders; difficult to strip down to the flat wireframe aesthetic and adds unnecessary D3 dependencies.
- **Pure 2D Canvas / SVG**: Cannot easily provide 3D perspective projection, orbital plane inclination rendering, camera orbital rotation, and raycasting without reinventing a 3D matrix math engine.

## 2. Satellite Orbit Propagation & Real-Time Calculation

### Decision
Use **`satellite.js`** (the standard JavaScript implementation of SGP4/SDP4 satellite orbit propagation) with live TLE (Two-Line Element) / GP ephemeris feeds.

### Rationale
- Complies strictly with Constitution Principle 1: "Live data only. Satellite positions come from a real tracking data source and are continuously recalculated. No hardcoded positions and no looped animations."
- SGP4 propagation calculates true Earth-Centered Inertial (ECI) coordinates for any instant in time (`Date.now()`), which convert to Geodetic latitude, longitude, altitude (km), and orbital speed (km/s).
- Orbit trail: Trajectory line is generated by sampling SGP4 propagation along the satellite's orbital plane (historical traveled path), rendered as an amber polyline in 3D world space.
- SGP4 calculation for 10 satellites takes <0.1ms per frame, ensuring steady 60 FPS performance.

### Decision
Ingest live tracking and SATCAT data directly from CelesTrak GP/SATCAT feeds for the 10 target satellites. Operational status (`Active` vs `Idle`/`Inactive`) is determined dynamically by evaluating the SATCAT `OPS_STATUS_CODE` (`+` = Active/Operational, `-` or `D` = Non-operational / Decayed, `—` = Unknown).

## 4. UI Architecture & Tech Stack

### Decision
**Vite + React 18 + TypeScript + Tailwind CSS**:
- Strict TypeScript interfaces for satellite models, orbital states, and telemetry.
- Three.js WebGL canvas managed in a dedicated viewport component.
- UI layer (top-left menu button, slide-in control panel, bottom-right telemetry HUD card) rendered using React with mission-control styling.
- LocalStorage store for user bookmarks ("Saved" section).

## 5. Design System Tokens & Typography

### Decision
Google Fonts:
- **`IBM Plex Mono`**: Applied to all data readouts, coordinates, speeds, altitudes, NORAD numbers, and timestamps.
- **`Schibsted Grotesk`**: Applied to labels, headers, button text, search bar, and general UI text.

Color Palette:
- `--bg-charcoal`: `#15171A`
- `--bg-panel`: `#181B1D`
- `--accent-amber`: `#E8A33D`
- `--text-offwhite`: `#E8E4D8`
- `--text-muted`: `#8E918B`
- `--border-hairline`: `1px solid #3A3E40`

Geometry & Transitions:
- `border-radius: 0px` strictly applied to all UI elements, inputs, reticles, and buttons.
- Control panel slide: `transform: translateX(0)` vs `translateX(-100%)` with `200ms cubic-bezier(0.16, 1, 0.3, 1)`.
- No other animations, gradients, or glassmorphism.
